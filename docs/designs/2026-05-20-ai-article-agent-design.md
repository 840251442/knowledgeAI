# AI 文章智能体设计

**Problem:** 后台写文章效率低，缺少一个可控的 AI 生成入口来根据关键词快速产出正文初稿。
**Solution:** 在后台编辑页增加 AI 创作入口，调用基于 LangChain 的文章智能体，通过流式返回将正文草稿展示在临时预览区，由用户手动决定是否插入正文。
**Out of scope:** 不生成标题、摘要、slug、分类、标签；不自动保存草稿；不接入站内知识检索；不做多轮对话工作流。

## Technical Approach

### 1. 架构分层

- 前端编辑器层：在文章编辑页新增 AI 创作入口、关键词输入、流式预览区、插入与放弃操作。
- API 路由层：新增后台流式接口，负责鉴权、参数校验、调用服务并输出 SSE。
- 智能体服务层：使用 LangChain 构建文章智能体，接收关键词并按约束生成 Markdown 正文，支持流式 token 输出。

### 2. 关键流程

1. 用户在后台编辑页点击 AI 创作。
2. 输入关键词并发起生成。
3. 前端请求流式接口。
4. 接口调用 LangChain 文章智能体并持续推送增量文本。
5. 前端临时预览区实时渲染生成内容。
6. 用户选择：
- 插入正文：将预览内容写入正文编辑器。
- 放弃：清空预览，不修改正文。

### 3. 流式协议

- 传输方式：SSE，响应 Content-Type 为 text/event-stream。
- 事件定义：
- delta：文本增量片段。
- done：生成完成。
- error：生成失败信息。
- 前端消费策略：按事件顺序拼接内容，遇到 done 停止，遇到 error 展示错误提示并允许重试。

### 4. LangChain 智能体策略

- 组件：单智能体链路，不引入工具调用，不做检索增强。
- 输入：关键词与基础写作约束。
- 输出：Markdown 正文。
- 约束：
- 默认中文。
- 结构清晰，段落可读。
- 最大长度不超过 2000 字。
- 不输出系统提示词、角色文本或元说明。

## Interface / Data Structures

### 1. 前端请求体

- keyword: string
- maxLength: number（默认 2000）
- style: string（可选，MVP 可省略）

### 2. SSE 事件载荷

- delta
- type: delta
- content: string

- done
- type: done

- error
- type: error
- message: string

### 3. 前端状态模型

- idle：未开始
- generating：流式生成中
- completed：已完成，可插入
- failed：生成失败，可重试

## Edge Cases

- 关键词为空：接口直接返回 400，前端提示请输入关键词。
- 重复点击生成：前端在 generating 状态禁用再次提交。
- 网络中断：前端进入 failed，保留已生成片段并支持重试。
- 用户中途关闭面板：主动中断连接，释放流式资源。
- 模型超时：接口输出 error 事件，前端提示超时并允许重试。
- 插入时正文已有内容：默认插入到光标处；若无法定位光标则追加到末尾。

## Acceptance Criteria

- [ ] 后台编辑页存在明确 AI 创作入口。
- [ ] 用户输入关键词后可触发流式生成。
- [ ] 临时预览区可实时显示增量正文。
- [ ] 生成内容长度不超过 2000 字。
- [ ] 用户可选择插入或放弃，默认不改动正文。
- [ ] 接口与前端对空关键词、超时、网络失败有可见错误提示。
- [ ] 插入正文动作稳定，不破坏现有编辑功能。
