# Article Editor Content Save Fix Design

**Problem:** 后台文章编辑时，正文更新后保存不上，导致再次查看时仍为旧内容，且问题在所有文章上可复现。
**Solution:** 采用服务端容错映射方案，在编辑保存接口层统一兼容历史正文字段并映射到唯一落库字段，保持前端改动最小；补充 1 条最小化 e2e 回归用例覆盖“编辑-保存-再次查看”闭环。
**Out of scope:** 富文本编辑器替换、批量迁移历史数据、全文索引策略重构。

## Technical Approach

- 在后台文章更新 API 的入参解析阶段新增正文字段兼容逻辑：兼容 `content` 与 `body`（以及现有主字段），统一归并到服务层使用的正文字段。
- 服务层只接受统一后的正文字段并执行更新，避免字段分叉导致“标题等字段更新成功但正文丢失”。
- 保持请求契约向后兼容：已有调用方无需立刻改造即可恢复正文保存。
- 增加保存链路日志或断言点（最小化）以便定位后续字段回归问题。
- 补充 1 条 e2e：后台编辑文章正文后保存，重新进入编辑页或详情页时可读到最新正文。

## Interface / Data Structures

- 后台更新接口输入：
  - 兼容读取字段：`content`、`body`、主字段（以当前实现为准）。
  - 归并规则：按优先级选择非空正文值并标准化到统一字段后下沉服务层。
- 服务层更新参数：
  - 仅消费统一字段，避免多字段并存写入歧义。

## Edge Cases

- 当多种正文字段同时存在且值不一致时，按预设优先级确定最终写入值，并记录可追踪信息。
- 当正文字段为空字符串时，遵循现有产品规则（允许清空或拦截校验）且保持与历史行为一致。
- 非正文字段更新不应受兼容映射影响。

## Acceptance Criteria

- [ ] 编辑文章后，正文可成功保存。
- [ ] 再次进入文章查看/编辑时，能看到最新正文。
- [ ] 旧调用方使用历史正文字段名提交时仍可保存成功。
- [ ] 仅进行最小范围改动，不引入无关重构。
- [ ] 新增 1 条 e2e 回归用例覆盖“编辑-保存-再次查看”。
