# KnowledgeAI 全站 UI 重构（基于 design-mockups）设计

**Problem:** 当前线上 UI 与最新 mockup 的视觉语言和交互规则不一致，导致体验割裂且审核效率低。  
**Solution:** 对现有前端进行一次全站 UI/UE 重构，统一到 mockup 的深色赛博风格、导航逻辑和弹窗交互，不改后端业务接口。  
**Out of scope:** 后端 API 重构、数据库结构调整、检索算法改造、权限模型变更、手机号验证码流程扩展。

## 技术方案

### 技术栈
- Next.js App Router + React + TypeScript
- Ant Design（`antd`）用于表单、按钮、下拉与反馈组件
- Markdown 编辑器：`@uiw/react-md-editor` 用于文章编辑与实时预览
- 现有 CSS 全局样式与局部 class 体系继续承担主题与布局控制

### 1. 设计目标
- 全站视觉语言统一到 docs/design-mockups 的当前版本（深色赛博科技风）。
- 公开站与后台在保持业务能力不变前提下，完成同一设计系统下的风格收敛。
- 交互优先遵循 mockup：
  - 顶部保留登录按钮，不单独展示注册按钮。
  - 登录弹窗内支持登录/注册切换。
  - 首页热门标签位置调整到搜索框下方。

### 2. 页面覆盖范围（全站）
- 公开站：
  - 首页
  - 搜索页
  - 文章列表页
  - 文章详情页
  - 公开认证页（保留作为降级入口）
- 后台：
  - 登录页（弹窗化视觉体验）
  - 管理框架布局（侧边栏、面板、表格、表单、状态区）
  - 文章/分类/标签/搜索日志等管理页（样式系统全覆盖）

### 3. 实施策略
- 样式层：
  - 以现有 class 体系为主（如 public.css / admin.css），进行主题重构，减少结构性破坏。
  - 抽取共享视觉 token（颜色、阴影、边框、半透明层级、按钮态、输入态）。
- 结构层：
  - 公开站布局调整为 mockup 导航结构。
  - 在公开站引入认证弹窗组件（登录/注册切换），注册入口收口到弹窗内部。
  - 首页信息块重排：搜索框后直接展示热门标签。
- 兼容层：
  - 保持现有 API 路径不变（/api/auth/*、/api/admin/*、/api/search 等）。
  - 保留 /auth 页面作为深链接与异常场景 fallback。

## 接口与数据结构

### 1. 不变接口（显式约束）
- 不新增后端接口。
- 不修改现有请求字段定义。

### 2. 前端状态结构（新增）
- 认证弹窗本地状态：
  - mode: login | register
  - fields: email/password（本期）
  - ui: open/loading/error/success
- 页面级视图状态：
  - public/admin 主题样式由路由布局控制
  - 组件仅消费样式，不承担权限判定逻辑

### 3. 组件边界
- 新增公开站认证弹窗组件：仅处理 UI 与请求发起。
- 保持服务层/数据层无改动：
  - src/services/*
  - src/lib/*
  - prisma/*

## 边界与异常场景

- 网络失败：弹窗与登录页统一错误提示视觉（不可吞错）。
- 会话已存在：打开登录弹窗时应可快速跳转或提示已登录态。
- 小屏适配：
  - 头部导航折行
  - 弹窗宽度与输入交互可用
  - 后台表格在移动端降级为单列块状信息
- 无数据场景：
  - 首页热门标签为空
  - 搜索无结果
  - 后台列表为空
  以上统一采用新视觉空态组件样式。

## 风险与权衡

- 风险 1：全站样式覆盖面大，易出现局部回归。
  - 缓解：分布局（public/admin）分批替换，逐页验收。
- 风险 2：历史页面内联样式与新主题冲突。
  - 缓解：逐步收敛内联样式到 CSS class，保留必要兜底。
- 风险 3：E2E 选择器依赖旧 DOM。
  - 缓解：保留 data-testid，避免破坏自动化用例锚点。

## 验收标准

- [ ] 全站视觉风格与 docs/design-mockups 当前稿一致（深色赛博主题、层级、边框、按钮状态）。
- [ ] 公开站顶部不再展示独立注册按钮，仅保留登录按钮。
- [ ] 登录弹窗内可切换到注册，并可完成注册流程（本期仅邮箱/密码）。
- [ ] 首页热门标签出现在搜索框下方，交互可点击。
- [ ] 后台布局、表格、表单、状态区已统一为新主题。
- [ ] 移动端主要页面无明显布局错乱（公开站 + 后台关键页）。
- [ ] 现有后端 API 与数据库层无改动。
- [ ] 现有关键 data-testid 不被破坏。

## 实施顺序建议

1. 公开站布局与主题 token 对齐（含首页重排）。
2. 公开站认证弹窗接入（登录/注册切换）。
3. 搜索/文章列表/详情页样式收敛。
4. 后台 layout 与登录页重构。
5. 后台管理页组件样式统一与移动端回归。
6. E2E 冒烟与视觉核对。
