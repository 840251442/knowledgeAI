# 文章编辑正文保存修复实施计划

## 背景与目标
- 问题：后台文章编辑时，正文更新后未正确落库，导致再次查看仍为旧内容（全量可复现）。
- 目标：在最小改动前提下恢复正文保存能力，并补充 1 条最小 e2e 回归用例。
- 对齐设计：docs/designs/2026-05-26-article-editor-content-save-fix.md

## 范围与非目标
- 范围：
  - 后台文章更新 API 入参正文兼容映射。
  - 服务层统一正文写入入口。
  - 1 条“编辑-保存-再次查看”e2e 回归。
- 非目标：
  - 不替换编辑器、不重构检索/索引策略、不做历史数据迁移。

## 任务拆解

### Task 1: 路由层正文兼容映射
- 修改文件（预期）：
  - `src/app/api/admin/articles/[id]/route.ts`
- 实施点：
  - 在 PUT 请求体中兼容读取 `content` / `body` / 当前主字段。
  - 按确定性优先级归并为单一正文参数，传给服务层。
  - 保持鉴权、响应结构与错误码语义不变。
- 验证：
  - `npm run typecheck`（若存在）
  - `npm run lint`
- 完成标准：
  - 历史字段提交正文也能更新成功。

### Task 2: 服务层统一正文写入
- 修改文件（预期）：
  - `src/services/admin-article.service.ts`
- 实施点：
  - 确认/收敛为单一正文写入路径，避免多字段分叉。
  - 不改变缓存失效与索引触发的既有行为。
- 验证：
  - `npm run typecheck`（若存在）
  - `npm run lint`
- 完成标准：
  - 正文更新只有一条明确写库路径。

### Task 3: 最小化 e2e 回归
- 修改文件（预期）：
  - `tests/e2e/admin-publish-cache.spec.ts`（优先复用）
  - 如需新增文件，保持仅 1 条用例。
- 实施点：
  - 覆盖“编辑正文 -> 保存 -> 再次查看正文为最新值”。
  - 用历史字段名提交一次，验证兼容保存链路。
- 验证：
  - `npm run test:e2e -- tests/e2e/admin-publish-cache.spec.ts`
- 完成标准：
  - 修复后用例可通过，能防止同类回归。

### Task 4: 门禁验证与交付记录
- 实施点：
  - 汇总 lint/typecheck/e2e 结果。
  - 判断 README 是否需要更新；若无需更新，明确原因。
  - 记录已验证项与未验证项。
- 验证：
  - `npm run lint`
  - `npm run typecheck`（若存在）
  - `npm run test:e2e -- tests/e2e/admin-publish-cache.spec.ts`
- 完成标准：
  - 验证证据齐全，可独立评审。

## 风险与回滚
- 风险：多字段同时存在且不一致时可能导致结果歧义。
- 风险：空字符串正文语义（清空还是忽略）需与现有行为保持一致。
- 回滚：优先回滚路由兼容映射，再回滚测试变更；保留失败样本用于二次修复。

## 里程碑顺序
1. M1：Task 1 完成并通过基础静态检查。
2. M2：Task 2 完成并确认服务层行为一致。
3. M3：Task 3 回归用例落地并通过。
4. M4：Task 4 质量门禁与交付说明完成。
