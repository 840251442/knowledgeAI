# 2026-05-22 Admin Auth Unification Implementation Plan

关联设计文档：`docs/designs/2026-05-22-admin-auth-unification-design.md`

## 目标
- 前台彻底移除登录入口与登录弹窗。
- 后台登录页升级为登录/注册 Tab（同页切换）。
- 当前仅开放邮箱注册/登录。
- 前后台共用一套权限体系：低权限可写作和发布，不能审核。

## 范围
- 包含：公开站导航、后台登录页、后台注册接口、审核权限控制、角色化菜单显示、E2E 回归。
- 不包含：手机号注册/登录、权限模型重构、审核流程规则重写。

## 实施步骤

### Phase 1 - 前台入口收口
- [x] 在公开站布局移除“登录”按钮。
- [x] 移除公开站登录弹窗组件挂载链路。
- [x] 清理前台认证入口相关无用状态与事件监听。
- [x] 若保留前台认证页面：改为提示/跳转后台登录页（二选一，按实现简洁优先）。

完成判定：公开站任意页面均不出现登录入口，不会弹登录框。

### Phase 3 - 后台注册接口与角色写入
- [x] 新增或封装后台注册接口（建议 `POST /api/admin/register`）。

- [x] 与会话写入逻辑保持一致（不破坏当前会话隔离方案）。

备注：当前后台注册入口复用 `POST /api/auth/register`（邮箱注册），未新增独立 `/api/admin/register` 路由。

完成判定：可通过后台页注册低权限账号并完成登录链路。

### Phase 4 - 权限门禁落地
- [x] 审核相关 API 增加高权限校验（低权限返回 403）。

- [x] 低权限账号保留文章写作与发布能力。
- [x] 高权限账号能力不回退。

备注：当前后台导航未新增审核菜单入口，低权限用户不存在可见审核入口；审核能力由服务端 API 角色校验兜底。

完成判定：低权限“可写作/可发布、不可审核”行为稳定可复现。

完成判定：关键链路测试通过，静态检查通过。

## 风险与应对
- 风险：前台认证链路移除后仍有残留入口。
  - 应对：全文搜索 `PublicAuthModal`、`/auth`、`personal-auth`，逐项清理。
- 风险：后台注册引入后，角色赋值与审核门禁不一致。
  - 应对：服务端权限校验作为唯一可信边界，前端仅做展示控制。
- 风险：会话策略改动引起登录态覆盖。
  - 应对：保持现有角色会话隔离逻辑不变，只扩展注册入口。
