# AI 在线知识库设计文档

**产品：** 面向公开访问的个人知识库，包含管理后台与 AI 增强搜索
**日期：** 2026-05-19
**状态：** 用于实施规划的设计草案

## 1. 目标

构建一个面向公众访问的个人知识库，支持以下能力：

- 作者自主发布和管理文章
- 分类与标签组织
- 快速关键词搜索
- 仅基于站内知识内容的 AI 语义搜索
- 基于 Vercel 部署，配套 MySQL 与 Redis

首个版本优先保证检索结果可信，而不是优先生成 AI 长回答。用户应该能够通过关键词或自然语言进行搜索，并获得相关的文章和命中片段。

## 2. 用户角色

- 访客：浏览公开内容并搜索知识库
- 管理员：登录后台，管理文章、分类、标签和发布状态

## 3. 范围

### 本期范围内

- 公开站点
- 管理后台
- 文章 CRUD
- 分类与标签管理
- Markdown 文章编辑与渲染
- 关键词搜索
- 基于站内内容的语义搜索
- 搜索日志记录
- Redis 缓存

### 本期范围外

- 聊天机器人式多轮 AI 助手

## 4. 架构设计

系统采用 Next.js 作为全栈应用框架：

- 在 App Router 中构建 React 界面
- 通过服务端处理公开 API 和后台 API
- 使用 MySQL 作为内容的主存储
- 使用 Redis 作为缓存和热点查询加速层
- 使用向量检索层对文章切片进行语义召回

### 检索模型

默认采用混合检索：

1. 对文章标题、摘要、标签和正文进行关键词召回
2. 对文章切片 embedding 进行语义召回
3. 对结果进行分数融合和最终排序

首个版本返回有来源依据的搜索结果，而不是直接输出长篇 AI 生成答案。

## 6. 主要流程

### 发布流程

1. 管理员使用 Markdown 编写或编辑文章
2. 管理员保存草稿或直接发布
3. 发布时，系统更新搜索索引状态
4. 系统对文章内容进行切片
5. 系统为切片生成 embedding
6. 清理受影响的搜索缓存键

### 搜索流程

1. 访客输入查询内容
2. 系统识别该查询是否适合语义检索
3. 系统并行执行关键词召回和语义召回
4. 合并并排序结果
5. 返回最相关的结果、摘要片段和元信息
6. 记录搜索日志

## 7. 质量属性

- 公开页面加载快
- 公开页面对 SEO 友好
- 后台管理安全，仅管理员可访问
- 内容管理与检索逻辑低耦合
- 索引流程适合异步处理

## 8. 交付策略

### 第一阶段

- 项目骨架
- 鉴权
- 文章、分类、标签 CRUD

### 第二阶段

- 公开页面
- SEO
- 关键词搜索

### 第三阶段

- 内容切片
- Embedding 生成
- 语义搜索
- 搜索分析

## 9. 风险点

- 向量检索方案的选择会影响延迟、成本和实现复杂度
- 同步生成 embedding 可能拖慢发布流程
- 切片质量差会直接降低语义搜索效果
- 在路由处理层混入过多业务逻辑会影响后续维护

## 10. 推荐方向

- 文章内容继续存放在 MySQL
- Redis 只承担缓存和热点结果存储职责
- Embedding 建议使用专门的向量服务或支持向量检索的数据库
- 首个版本聚焦检索能力，不优先做答案生成
